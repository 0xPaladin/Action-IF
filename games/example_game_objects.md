# Example Game Objects

This document provides JSON examples of every game object type used in the Action-IF engine. Each section shows the object structure, all fields, and a concrete example. Game definitions live in folders under `games/` — each folder contains a `game.json` (the main definition) and optionally additional JSON files (e.g. `zones.json`, `factions.json`) that are merged together, plus an optional `hooks.js` for custom hook handlers. The merged definition object is passed to `createGame(definition)` in `src/engine.js`.

The top-level definition object accepts a `name` field (string) that sets the game's display name in the WebUI header.

## Zone

Zones form the spatial hierarchy of the game world. The hierarchy (largest to smallest) is:

```
galaxy > expanse > sector > reach > subsector > cluster > system > world > realm > region > area > site
```

`children` are auto-generated by `generateZoneNodeGraph(state)` from `parent` references.

```json
{
  "id": "junction",
  "type": "realm",
  "name": "Junction — The Nexus City",
  "description": "The heart of the Verse. A kaleidoscopic city of infinite wards, where gates pulse with travelers from a thousand worlds.",
  "parent": null,
  "links": []
}
```

```json
{
  "id": "guardian_hq",
  "type": "site",
  "name": "Guardian Nexus Operations",
  "description": "A gleaming forward operations base within Junction, housing tactical command and mission control.",
  "parent": "junction",
  "links": []
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique zone identifier |
| `type` | `string` | One of the hierarchy levels above |
| `name` | `string` | Display name |
| `description` | `string` | Flavor text |
| `parent` | `string \| null` | Parent zone ID (`null` for root) |
| `links` | `Link[]` | Structural navigation links (auto-generated) |

## Location

Locations are leaf nodes where characters actually exist. They are nested inside zones.

```json
{
  "id": "ops_center",
  "name": "Operations Center",
  "description": "Holographic star-maps project the Vorath sector in shimmering blue light. Threat markers pulse along contested borders.",
  "parent": "guardian_hq",
  "links": [
    { "targetId": "briefing_room", "label": "Briefing Room" },
    { "targetId": "guardian_hq_atrium", "label": "Return to Atrium" }
  ],
  "actions": [
    {
      "id": "review_intel",
      "label": "Review Intel",
      "description": "Study intercepted Hegemony communications.",
      "once": false,
      "setFlag": "intel_reviewed"
    },
    {
      "id": "start_mission",
      "label": "Start Mission",
      "description": "Begin Operation Echoes in the Void.",
      "once": true,
      "condition": { "flag": "vorath_mission_ready" },
      "triggerScene": "engagement_launch"
    }
  ]
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique location identifier |
| `name` | `string` | Display name |
| `description` | `string` | Shown when entering |
| `parent` | `string` | Parent site zone ID |
| `links` | `Link[]` | Manual navigation links only |
| `actions` | `Action[]` | Available actions at this location |
| `mayChangeInventory` | `boolean` | If `true`, players can change gear at this location (default `false`) |

## Link

Links connect locations. They may be hidden (via `condition`) or locked (via `key`). When a link has a `journey`, the player plays through the journey scenes before transitioning to the target. Journey scenes can optionally reference **encounters** — free scenes defined in the top-level `encounters` array (see [Encounter](#encounter) section).

```json
{
  "targetId": "guardian_hq_atrium",
  "label": "Return to Atrium",
  "condition": null,
  "locked": false,
  "key": null
}
```

```json
{
  "targetId": "vault",
  "label": "Vault Door",
  "condition": { "flag": "vault_unlocked" },
  "locked": true,
  "key": "vault_key"
}
```

```json
{
  "targetId": "distant_outpost",
  "label": "Travel to Outpost",
  "condition": null,
  "locked": false,
  "key": null,
  "journey": [
    {
      "id": "encounter1",
      "type": "action",
      "fiction": "A patrol blocks the path.",
      "tags": ["outdoor"],
      "challenges": [
        {
          "id": "fight_patrol",
          "description": "Defeat the patrol",
          "clockMax": 4,
          "tags": ["combat"],
          "actions": [
            { "actionName": "Muscle", "consequences": { "description": "You take harm.", "template": "harm", "params": { "amount": 1 } } }
          ]
        }
      ]
    }
  ]
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `targetId` | `string` | Target location ID |
| `label` | `string` | Display text |
| `condition` | `object \| null` | Prerequisite (see [Condition](#condition)) |
| `locked` | `boolean` | Requires `key` flag when `true` |
| `key` | `string \| null` | Flag required to unlock |
| `journey` | `SceneDef[] \| null` | Optional scenes played during travel between distant locations |

Links with failing conditions are invisible. Locked links are visible but crossing them fails unless `state.flags[key]` is set.

When a link has a `journey`, the player does not transition to the target immediately. Instead, the journey scenes are played in order — each scene may contain challenges or dialogue options. After all journey scenes are resolved, the player transitions to the target location.

Journey scenes can optionally reference an **encounter** — a free scene defined in the game's top-level `encounters` array (see [Encounter](#encounter) section). When a journey scene has an `encounter` key, the encounter scene is activated instead of the journey scene. After the encounter resolves, the journey continues.

```json
{
  "targetId": "distant_outpost",
  "label": "Travel to Outpost",
  "journey": [
    {
      "type": "dialogue",
      "fiction": "The road ahead stretches through the wastes...",
      "tags": [],
      "options": [{ "text": "Press on" }],
      "encounter": "enc_bandits"
    }
  ]
}
```

Weighted random encounter selection:

```json
{
  "encounter": [["enc_bandits", "enc_patrol", ""], [10, 5, 1]]
}
```

If the selected ID is `""`, the encounter is skipped and the journey scene is resolved normally.

## Encounter

Encounters are free scenes not linked to a plotline — random encounters while traveling or exploring. Defined in the top-level `encounters` array of the game definition. They can be `"action"` or `"dialogue"` type scenes.

```json
{
  "id": "enc_bandits",
  "type": "action",
  "fiction": "Bandits block the road! A rusty barricade and four thugs with crossbows stand between you and your destination.",
  "tags": ["outdoor", "combat"],
  "heat": false,
  "challenges": [
    {
      "id": "fight_bandits",
      "description": "Defeat the bandits and clear the road.",
      "clockMax": 4,
      "tags": ["combat"],
      "actions": [
        {
          "actionName": "Muscle",
          "consequences": {
            "description": "A crossbow bolt grazes your arm.",
            "template": "harm",
            "params": { "amount": 1 }
          }
        },
        {
          "actionName": "Sway",
          "consequences": {
            "description": "They don't trust your words.",
            "template": "condition",
            "params": { "condition": "marked" }
          }
        }
      ]
    }
  ]
}
```

Dialogue encounter:

```json
{
  "id": "enc_traveler",
  "type": "dialogue",
  "fiction": "A lone traveler approaches with a warning about the road ahead...",
  "tags": ["social"],
  "heat": false,
  "options": [
    {
      "text": "Listen to their warning",
      "setFlag": "traveler_warning"
    },
    {
      "text": "Ignore them and press on",
      "hooks": { "type": "log", "text": "You push past the traveler." }
    }
  ]
}
```

## Action

Actions are physical things characters can do at a location (search, activate a lever, etc.) or interact with an NPC. They may trigger a scene, provide keys, set flags, or resolve hooks. The same `Action` object is used for both location actions and NPC actions — NPC actions simply appear grouped under their NPC in the UI.

```json
{
  "id": "start_mission",
  "label": "Start Mission",
  "description": "Begin Operation Echoes in the Void — gate to Waystation Vorath.",
  "once": true,
  "used": false,
  "triggerScene": "engagement_launch",
  "setFlag": "mission_started",
  "provideKeys": ["gate_key"],
  "condition": { "flag": "vorath_mission_ready" },
  "hooks": { "type": "log", "text": "Mission initiated." }
}
```

NPC action example (appears under the NPC in the location context):

```json
{
  "id": "offer_mission",
  "label": "Request Mission Briefing",
  "description": "Ask Commander Valeria for mission details.",
  "once": true,
  "used": false,
  "triggerScene": "npc:valeria:introduction",
  "setFlag": "briefing_received",
  "provideKeys": ["gate_key"],
  "condition": null,
  "hooks": { "type": "log", "text": "Mission briefing received." }
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique action identifier |
| `label` | `string` | Display text |
| `description` | `string` | Shown when selected |
| `once` | `boolean` | `true` = can only be performed once |
| `used` | `boolean` | Runtime: tracks if a once-action has been used |
| `triggerScene` | `string \| null` | Scene ID to enter when used |
| `setFlag` | `string \| null` | Flag to set when used |
| `provideKeys` | `string[]` | Keys (flags) granted when used |
| `condition` | `object \| null` | Prerequisite (see [Condition](#condition)) |
| `hooks` | `Hook \| Hook[] \| null` | Declarative hook(s) to resolve (see [Hook](#hook)) |

## Character

Characters have 12 actions rated 0–4. At creation, 7 action dots are distributed (max 2 per action).

```json
  {
   "name": "Valeria Steelforged",
   "actions": {
    "Muscle": 2, "Move": 0, "Finesse": 0, "Sneak": 0,
    "Shoot": 0, "Tinker": 0, "Study": 0, "Notice": 1,
    "Bond": 0, "Command": 2, "Focus": 1, "Sway": 0
  },
  "guard": 3,
  "maxGuard": 3,
  "body": 6,
  "conditions": [],
  "inventory": [],
   "stunts": ["inspiring_presence"],
  "stuntChoices": [],
  "healing": null,
  "load": 0,
  "maxLoad": 5,
  "xp": 0,
   "projects": [],
   "downtimeRemaining": 0,
   "aspects": ["The Unbroken Shield", "Oath of the Celestial"]
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `name` | `string` | Character name |
| `actions` | `object` | All 12 actions, each 0–4 |
| `guard` | `number` | 0–maxGuard; absorbs harm first, resets each scene |
| `maxGuard` | `number` | Max guard capacity (default 3, max 5 via fortify project) |
| `body` | `number` | 0–6; persistent; ≤0 = incapacitated |
| `conditions` | `string[]` | Tags consuming 1 load each, −1d per match |
| `inventory` | `Item[]` | Carried items |
| `stunts` | `string[]` | Stunt IDs from the top-level `stunts` array |
| `stuntChoices` | `StuntDef[]` | Available stunts for level-up |
| `healing` | `object \| null` | 4-tick healing clock |
| `load` | `number` | Current total load from inventory |
| `maxLoad` | `number` | Max load capacity (set via `setLoadLevel`) |
| `xp` | `number` | Experience points earned |
| `projects` | `Project[]` | Long-term projects |
| `downtimeRemaining` | `number` | Activities remaining (2 per downtime phase) |
| `aspects` | `string[]` | Optional Fate-style aspects |

### Character Creation Helpers

- `createCharacter(name)` — returns a fresh character with all actions at 0, Guard 3, Body 6.
- `assignActionDots(character, dots)` — takes an array of 12 integers (each 0–2, summing to 7).

## Item

Items are objects characters can carry. They have load cost and effects that work identically to stunts.

```json
{
  "id": "aurumite_plate",
  "name": "Aurumite Plate",
  "description": "Celestial power armor — reduces incoming harm by 1 in protective contexts",
  "load": 2,
  "tags": ["protective"],
  "action": "Muscle",
  "bonusDice": 1,
  "bonusTicks": 0,
  "armor": 1
}
```

```json
{
  "id": "engineering_kit",
  "name": "Engineering Kit",
  "description": "Tools for any job",
  "load": 2,
  "tags": ["tech"],
  "action": "Tinker",
  "bonusDice": 1,
  "bonusTicks": 0,
  "armor": 0
}
```

```json
{
  "id": "plasma_sword",
  "name": "Plasma Sword",
  "description": "A mono-molecular blade that only Valeria can wield effectively.",
  "load": 1,
  "tags": ["combat", "energy"],
  "effects": { "action": "Muscle", "bonusDice": 1, "bonusTicks": 0, "armor": 0 },
  "specialized": true
}
```

```json
{
  "id": "ancient_relic",
  "name": "Ancient Relic",
  "description": "A crystalline shard humming with forgotten power — found deep within the archive.",
  "load": 0,
  "tags": ["ancient"],
  "effects": { "bonusDice": 1 },
  "individual": true
}
```

```json
{
  "id": "plasma_sword",
  "name": "Plasma Sword",
  "description": "A mono-molecular blade that only Valeria can wield effectively.",
  "load": 1,
  "tags": ["combat", "energy"],
  "action": "Muscle",
  "bonusDice": 1,
  "bonusTicks": 0,
  "armor": 0,
  "specialized": true
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique item identifier |
| `name` | `string` | Display name |
| `description` | `string` | Flavor text |
| `load` | `number` | Load cost while carried |
| `tags` | `string[]` | Matched against scene + challenge tags |
| `action` | `string \| null` | If set, bonusDice/bonusTicks/bonusEffect only apply when this action is rolled |
| `bonusDice` | `number` | +1d per point (requires action + tags match) |
| `bonusTicks` | `number` | +1 extra tick per point on challenge clock (requires action + tags match) |
| `bonusEffect` | `number` | +1 effect level per point (requires action + tags match) |
| `armor` | `number` | Reduces incoming harm by N when tags match |
| `substituteAction` | `object \| null` | `{ from, to }` — roll `to` instead of `from` |
| `specialized` | `boolean` | If `true`, item effects only apply to characters with this item's `id` in their inventory, and the item only appears in loadout for characters with this ID in their `items` array (default `false`) |
| `individual` | `boolean` | If `true`, the item is a unique one-of-a-kind item that must be found or granted through actions/scenes. It does NOT appear in loadout selection. If lost via a consequence, it is gone until re-granted (default `false`) |

## Inventory & Loadout

The inventory system behaves differently **off-mission** vs **on-mission**.

### Item Classifications

Each item in the top-level `items` array has an implicit classification based on two optional fields:

| Classification | `specialized` | `individual` | Behavior |
|---|---|---|---|
| **General** | `false` / absent | `false` / absent | Available to all characters during loadout |
| **Specialized** | `true` | `false` / absent | Only available to characters whose `items` array includes this item's ID |
| **Individual** | — | `true` | Never available in loadout. Must be granted at runtime via hooks, projects, or NPC actions |

### Off-Mission

- Max load is always **10**
- Characters start with an empty inventory
- Gear can only be changed at locations with `mayChangeInventory: true`
- Items can be dropped at any time
- Available items for loadout = general items + specialized items (from character's `items` array)
- Individual items already in inventory are displayed in a separate "Special Items" section and cannot be dropped through the gear panel (only via `loseItem` consequences)

### On-Mission

- Before the mission, set load level via `loadlevel <light|normal|heavy>` (default `normal` = 5)
- Characters start with an empty inventory (cleared by the engagement hook)
- Available items for loadout = general items + specialized items (from character's `items` array)
- Once an item is selected (checkmarked), it **cannot be dropped** during the mission
- Max load is determined by the load level setting
- Individual items can be found during the mission and added to inventory; they persist in inventory after the mission ends

## Stunt

Stunts are character abilities that trigger when tags match the active scene or challenge. All stunt objects are defined in a top-level `stunts` array in the game definition; characters and crew types reference them by ID.

```json
{
  "id": "adamantine_guard",
  "name": "Adamantine Guard",
  "description": "+1d when protecting allies in scenes tagged protective",
  "tags": ["protective"],
  "action": "Muscle",
  "bonusDice": 1,
  "bonusTicks": 0,
  "bonusEffect": 0,
  "substituteAction": null
}
```

```json
{
  "id": "system_interface",
  "name": "System Interface",
  "description": "Substitute Tinker for Study when analyzing technology",
  "tags": ["tech", "ancient"],
  "action": null,
  "bonusDice": 0,
  "bonusTicks": 0,
  "bonusEffect": 0,
  "substituteAction": { "from": "Study", "to": "Tinker" }
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique stunt identifier |
| `name` | `string` | Display name |
| `description` | `string` | Flavor text |
| `tags` | `string[]` | Matched against scene + challenge tags |
| `action` | `string \| null` | If set, bonusDice/bonusTicks/bonusEffect only apply when this action is rolled |
| `bonusDice` | `number` | +1d per point (requires action + tags match) |
| `bonusTicks` | `number` | +1 extra tick per point on challenge clock (requires action + tags match) |
| `bonusEffect` | `number` | +1 effect level per point (requires action + tags match) |
| `substituteAction` | `object \| null` | `{ from, to }` — roll `to` instead of `from` |

## Scene — Action

Action scenes have **challenges** — obstacles resolved via action rolls.

```json
{
  "id": "infiltrate_scene",
  "type": "action",
  "fiction": "The Listening Post's interior is a cathedral of alien design. Bio-silk membranes pulse with dim light. Two obstacles stand between you and the archive: a sealed security door and a patrol of thrall guards.",
  "tags": ["tech", "dark", "ancient"],
  "heat": true,
  "challenges": [
    {
      "id": "security_door",
      "description": "A crystalline Hegemony security door — requires technical skill or precision manipulation to bypass.",
      "clockMax": 4,
      "tags": ["tech", "ancient"],
      "actions": [
        {
          "actionName": "Tinker",
          "consequences": {
            "description": "The door's alarm system triggers.",
            "template": "tickClock",
            "params": { "amount": 1 }
          }
        }
      ],
      "onComplete": [
        { "type": "log", "text": "Security door bypassed." }
      ]
    }
  ],
  "onEnter": [
    { "type": "log", "text": "The team enters the Listening Post." }
  ],
  "onExit": { "type": "setFlag", "flag": "archive_unlocked" },
  "resolved": false
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique scene identifier |
| `type` | `"action"` | Scene type |
| `fiction` | `string` | Narrative text displayed to player |
| `tags` | `string[]` | e.g. `["outdoor", "night", "social"]` |
| `challenges` | `Challenge[]` | Obstacles to overcome |
| `heat` | `boolean` | Whether this scene generates mission heat (default `false`) |
 | `onEnter` | `Hook \| Hook[] \| null` | Fires when set as active scene |
 | `onExit` | `Hook \| Hook[] \| null` | Fires when scene becomes resolved |
 | `resolved` | `boolean` | Runtime: `true` when all challenges resolved |

## Scene — Dialogue

Dialogue scenes present the player with a set of **options** (choices). They can be standalone scenes nested in plotlines or encounters, or they can be NPC dialogue trees compiled into scenes at game creation time with IDs prefixed `npc:{npcId}:{dialogueId}`.

```json
{
  "id": "npc:valeria:introduction",
  "type": "dialogue",
  "fiction": "Commander Valeria looks up from the tactical display as you approach. 'Good. You're here. The situation in Vorath's Reach has escalated.'",
  "tags": ["guardian", "briefing"],
  "heat": false,
  "options": [
    {
      "text": "Stealth approach — infiltrate undetected",
      "setFlag": "stealth_approach",
      "hooks": { "type": "setFlag", "flag": "vorath_mission_ready" }
    },
    {
      "text": "Direct assault — overwhelming force",
      "setFlag": "assault_approach",
      "hooks": { "type": "setFlag", "flag": "vorath_mission_ready" }
    },
    {
      "text": "Social engineering — talk our way in",
      "hooks": { "type": "setFlag", "flag": "vorath_mission_ready" }
    }
  ],
  "onEnter": null,
  "onExit": null,
  "triggerScene": null,
  "resolved": false
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Scene ID (NPC dialogues use `npc:{npcId}:{dialogueId}` prefix) |
| `type` | `"dialogue"` | Scene type |
| `fiction` | `string` | Narrative text displayed to player |
| `tags` | `string[]` | e.g. `["outdoor", "night", "social"]` |
| `heat` | `boolean` | Whether this scene generates mission heat (default `false`) |
| `options` | [Option](#option)[] | Player choices |
| `onEnter` | `Hook \| Hook[] \| null` | Fires when set as active scene |
| `onExit` | `Hook \| Hook[] \| null` | Fires when scene becomes resolved |
| `triggerScene` | `string \| null` | Scene to transition to when this scene resolves (if no option provides its own) |
| `resolved` | `boolean` | Runtime: `true` after an option is selected |

### NPC Dialogue

NPC dialogue trees are defined in the `dialogue` array of an NPC definition. At game creation, the engine compiles each entry into a dialogue scene with the id `npc:{npcId}:{dialogueId}`. Options may use `triggerScene` to chain to another dialogue — if the value matches a sibling dialogue id, it is automatically prefixed with `npc:{npcId}:`; otherwise it is treated as an absolute scene id.

```json
{
  "id": "introduction",
  "fiction": "Commander Valeria looks up from the tactical display as you approach. 'Good. You're here. The situation in Vorath's Reach has escalated.'",
  "tags": ["guardian", "briefing"],
  "options": [
    {
      "text": "Stealth approach — infiltrate undetected",
      "setFlag": "stealth_approach",
      "hooks": { "type": "setFlag", "flag": "vorath_mission_ready" }
    },
    {
      "text": "Direct assault — overwhelming force",
      "setFlag": "assault_approach",
      "hooks": { "type": "setFlag", "flag": "vorath_mission_ready" }
    }
  ],
  "onEnter": null,
  "onExit": null
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique dialogue identifier (becomes `npc:{npcId}:{id}` at runtime) |
| `fiction` | `string` | NPC dialogue text |
| `tags` | `string[]` | For stunts/items matching |
| `options` | [Option](#option)[] | Player choices |
| `onEnter` | `Hook \| Hook[] \| null` | Fires when dialogue is entered |
| `onExit` | `Hook \| Hook[] \| null` | Fires when dialogue is resolved |

## Challenge

Each challenge is an obstacle the crew must overcome.

```json
{
  "id": "security_door",
  "description": "A crystalline Hegemony security door — requires technical skill or precision manipulation to bypass.",
  "clock": { "max": 4, "current": 0 },
  "tags": ["tech", "ancient"],

    {
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique challenge identifier |
| `description` | `string` | Short obstacle description |

| `tags` | `string[]` | e.g. `["locked", "arcane", "guarded"]` |

| `resolved` | `boolean` | Runtime: `true` when clock fills |
| `defaultEffect` | `string` | Base effect level: `"great"`, `"standard"`, `"limited"`, or `"none"` (default `"standard"`) |

| `onComplete` | `Hook \| Hook[] \| null` | Fires when clock fills |

## Consequence

Consequences are registered templates that mutate game state. Applied on failure only.

### Built-in Templates

```json
{
  "description": "Patrol drones detect you — alarm raised.",
  "template": "tickClock",
  "params": { "amount": 1 }
}
```

```json
{
  "description": "K'tharr's shadow tendril strikes you.",
  "template": "harm",
  "params": { "amount": 3 }
}
```

```json
{
  "description": "Your team is pinned down.",
  "template": "condition",
  "params": { "condition": "pinned" }
}
```

```json
{
  "description": "You trigger a security trap.",
  "template": "loseItem",
  "params": { "itemId": "engineering_kit" }
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `description` | `string` | Narrative text displayed to player |
| `template` | `string` | Registered template: `"harm"`, `"condition"`, `"tickClock"`, `"loseItem"` |
| `params` | `object` | Template-specific parameters |

### Template Parameter Reference

| Template | Params | Effect |
|---|---|---|
| `harm` | `amount` (default 1) | Reduces Guard then Body; reduced by matching `armor` items |
| `condition` | `condition` (tag name) | Adds tag to `character.conditions[]`; uses 1 load slot |
| `tickClock` | `amount` (default 1) | Advances the mission's 4-segment danger clock |
| `loseItem` | `itemId` (optional) | Removes an item from inventory; falls back to last item |

String-only consequences (narrative text) are also supported.

## FactionClock

Faction clocks are faction-level progress clocks that trigger state changes when they fill.

```json
{
  "id": "hegemony_response",
  "name": "Hegemony Response",
  "description": "The Hegemony is alerted to Guardian activity in Vorath's Reach.",
  "clock": { "max": 6, "current": 0 },
  "completed": false,
  "onComplete": null
}
```

**Fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique clock identifier |
| `name` | `string` | Display name |
| `description` | `string` | Flavor text |
| `clock` | `object` | `{ max, current }` |
| `completed` | `boolean` | Runtime: `true` when clock fills |
 | `onComplete` | `Hook \| Hook[] \| null` | Fires when clock fills |

### Triggers

Faction clocks can be ticked from three places:

1. **Dialogue options** — `tickFactionClock: { id, amount }` on the option
2. **Challenges** — `tickFactionClock: { id, amount }` on the challenge (fires when challenge clock fills)
3. **Scene resolution** — `tickFactionClockOnResolve: { id, amount }` on the scene (fires when entire scene resolves)

```json
{
  "id": "archive_scene",
  "type": "dialogue",
  "fiction": "The archive core opens into a vast chamber...",
  "tags": ["ancient", "social"],
  "heat": false,
  "options": [
    {
      "text": "Attempt to negotiate — offer her safe passage",
      "tickFactionClock": { "id": "hegemony_response", "amount": 1 }
    }
  ]
}
```

## Hook

Hooks provide a declarative mechanism for state changes in game definitions. They are the primary way to trigger effects: scene `onEnter`/`onExit`, challenge `onAct`/`onComplete`, mission `onComplete`, location action `hooks`, claim template `apply`/`remove`, and others.

### Built-in Hook Types

| Type | Params | Effect |
|---|---|---|
| `setFlag` | `flag` | Sets `state.flags[flag] = true` |
| `clearFlag` | `flag` | Deletes `state.flags[flag]` |
| `tickClock` | `clockId`, `amount` (1) | Ticks a faction clock |
| `addHeat` | `amount` (2) | Adds heat to crew |
| `addRep` | `amount` (1) | Adds rep to crew |
| `addCoin` | `amount` (2) | Adds coin to crew |
| `addXp` | `amount` (2) | Adds XP to crew |
| `spendCoin` | `amount` (2) | Deducts coin from crew |
| `setScene` | `sceneId` | Transitions to a scene |
| `encounter` | `encounter` | Triggers an encounter scene (string ID or `[idArray, weightArray]`) |
| `log` | `text` | Adds a log entry |
| `adjustStatus` | `factionId`, `delta` (1) | Adjusts faction heat (positive = more heat, negative = more favor) |
| `clearActiveScene` | — | Exits the current scene |
| `message` | `text` | Logs a message entry |
| `completePlotline` | `plotlineId` | Marks a plotline completed |
| `setLocation` | `locationId` | Moves the player to a location |
| `rest` | `characterIndex` (0) | Clears conditions and recalculates load |
| `healHarm` | `characterIndex` (0) | Restores +1 Body then +1 Guard |
| `engagement` | — | Rolls engagement and activates the current plotline's mission |
| `completeMission` | — | Applies mission payoff, heat, faction standing, clears active mission, enters downtime |
| `giveItem` | `itemId`, `characterIndex` (0) | Adds an item to a character's inventory |
| `takeItem` | `itemId`, `characterIndex` (0) | Removes an item from a character's inventory |
| `addCondition` | `condition`, `characterIndex` (0) | Adds a condition tag to a character |
| `removeCondition` | `condition`, `characterIndex` (0) | Removes a specific condition tag from a character |
| `clearConditions` | `characterIndex` (0) | Clears all condition tags from a character |
| `dealHarm` | `amount` (1), `characterIndex` (0), `tags` ([]) | Deals harm (armor-reduced) to a character's Guard then Body |
| `resetGuard` | `characterIndex` (0) | Restores a character's guard to maxGuard |
| `addCharacterXp` | `amount` (1), `characterIndex` (0) | Adds XP to a specific character |
| `moveNPC` | `npcId`, `locationId` | Moves an NPC to a different location |
| `removeNPC` | `npcId` | Removes an NPC from the game world |
| `addClock` | `id`, `name`, `description`, `clockMax` (4), `onComplete` | Creates a new faction clock at runtime |
| `removeClock` | `clockId` | Removes a faction clock from the game |
| `modifyAction` | `action`, `delta` (1), `characterIndex` (0), `permanent` (false) | Adjusts a character's action rating (permanent or temporary) |

### Single Hook Object

```json
{ "type": "setFlag", "flag": "met_contact" }
```

### Hook Array

```json
[
  { "type": "setFlag", "flag": "met_contact" },
  { "type": "adjustStatus", "factionId": "lampblacks", "delta": 1 }
]
```

### Custom Hook Types

```js
registerHook("myEffect", (state, params, context) => {
  state.flags[params.flag] = params.value;
});
```

### Hook Usage Examples

```json
{
  "scenes": [
    {
      "id": "meet_contact",
      "type": "dialogue",
      "fiction": "You meet your contact in the shadows.",
      "onEnter": { "type": "log", "text": "The contact eyes you warily." },
      "onExit": [
        { "type": "setFlag", "flag": "met_contact" },
        { "type": "adjustStatus", "factionId": "lampblacks", "delta": 1 }
      ],
      "options": [
        { "text": "Take the job" }
      ]
    }
  ],
  "locations": [
    {
      "id": "bar",
      "name": "The Broken Cask",
      "description": "A dimly lit tavern.",
      "actions": [
        {
          "id": "rumors",
          "label": "Listen for rumors",
          "description": "Eavesdrop on the crowd.",
          "hooks": { "type": "addCoin", "amount": 1 }
        }
      ]
    }
  ]
}
```

#### Encounter Hook

The `encounter` hook triggers a free encounter scene — the same mechanism used by journey links. It accepts a string ID or a weighted `[idArray, weightArray]` for random selection.

```json
{
  "encounters": [
    {
      "id": "enc_bandits",
      "type": "action",
      "fiction": "Bandits block the road!",
      "tags": ["outdoor", "combat"],
      "heat": false,
      "challenges": [
        {
          "id": "fight",
          "description": "Defeat the bandits",
          "clockMax": 4,
          "tags": ["combat"],
          "actions": [
            { "actionName": "Muscle", "consequences": { "description": "You take harm.", "template": "harm", "params": { "amount": 1 } } }
          ]
        }
      ]
    }
  ],
  "locations": [
    {
      "id": "trailhead",
      "name": "Trailhead",
      "description": "The road begins here.",
      "actions": [
        {
          "id": "travel",
          "label": "Travel down the road",
          "description": "Venture into the wilderness.",
          "hooks": { "type": "encounter", "encounter": "enc_bandits" }
        }
      ]
    }
  ]
}
```

Weighted random encounter:

```json
{
  "hooks": { "type": "encounter", "encounter": [["enc_bandits", "enc_patrol", ""], [10, 5, 1]] }
}
```

#### Item and Condition Hooks

The `giveItem`, `takeItem`, `addCondition`, `removeCondition`, and `clearConditions` hooks let you manipulate character state declaratively — useful for quest rewards, consequences, and healing.

```json
{
  "scenes": [
    {
      "id": "loot_cache",
      "type": "dialogue",
      "fiction": "You find a hidden cache of supplies.",
      "tags": [],
      "options": [
        {
          "text": "Take the plasma rifle",
          "hooks": [
            { "type": "giveItem", "itemId": "plasma_rifle", "characterIndex": 0 },
            { "type": "setFlag", "flag": "rifle_taken" }
          ]
        },
        {
          "text": "Leave it untouched",
          "hooks": { "type": "addCondition", "condition": "honorable", "characterIndex": 0 }
        }
      ]
    }
  ]
}
```

The `dealHarm` and `resetGuard` hooks let you apply damage or restore guard outside of challenge consequences — for traps, environmental hazards, or mid-scene healing.


#### Clock and Action Modification Hooks

The `addClock`, `removeClock`, and `modifyAction` hooks let you create dynamic world timers and apply temporary or permanent action rating changes.

```json
{
  "scenes": [
    {
      "id": "library_blessing",
      "type": "dialogue",
      "fiction": "The ancient library grants you clarity.",
      "tags": ["knowledge"],
      "options": [
        {
          "text": "Accept the blessing",
          "hooks": [
            { "type": "modifyAction", "action": "Study", "delta": 1, "characterIndex": 0 },
            { "type": "addClock", "id": "blessing_timer", "name": "Library Blessing", "description": "The blessing fades after 3 scenes.", "clockMax": 3 }
          ]
        }
      ]
    }
  ]
}
```
